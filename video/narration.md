## Slide 1, title (12s)

Are NBFNet's path explanations actually faithful? I test that with deletions
and edits on a frozen knowledge graph reasoner. This is a research track
project.

---

## Slide 2, what this project does (55s)

A knowledge graph query asks for a missing link: here, which religion Samuel
Delany holds. NBFNet answers by passing messages along paths in the graph, and
it explains itself from the same computation. It takes the gradient of the
score with respect to every edge and beam searches the top paths. Those paths
are presented as the reason for the answer, and that is the main argument for
path models over embeddings.

But a gradient only says what happens if an edge changes a little. Whether the
model relied on an edge is a question about taking it away. So this project
does not inspect the explanation. It changes the graph and checks whether the
answer moves, which is the lesson of topic eight, on a graph where the edit is
exact.

---

## Slide 3, five interventions (55s)

There are five conditions. A calls NBFNet's own visualize function and records
what it claims. B deletes each of its twenty candidate paths, one at a time, so
the method's ranking can be set against the real effect. C deletes the top five
together, or keeps only them. D points the last hop of the top path at a
different entity, and checks whether the answer follows. E turns a whole
relation channel down, which I will come back to.

Every condition removes or rewires real edges and reruns the released
checkpoint. Nothing is trained and nothing is approximated. And every result
has a control: the same number of random edges, the bottom of the method's own
list, the tail's degree, and whether the reverse fact is already in the graph.

---

## Slide 4, the benchmark (45s)

The benchmark covers four graphs. WN18RR and FB15k-237 were in the
checkpoint's training mixture. CoDEx-S and NELL23k were not. On each one I
first reproduce link prediction on the full test set with ULTRA's own
evaluation code, and those MRRs are in the table.

Then 800 queries, drawn in a random order that was fixed before
anything was measured, so nothing is picked by hand. A query is kept when the
model ranks the right answer in its top ten. That gives 15,447
single-path deletions, plus the joint deletions, controls and rewires. The
model is deterministic, so all the variance is across queries, and every
interval is a bootstrap over them.

---

## Slide 5, is that enough queries (50s)

Is that enough? I checked instead of assuming. Because the order was fixed in
advance, the first n queries are an honest sample of size n. Each curve is the
running estimate with its 95 percent band as queries are added. The bands
narrow roughly as one over the square root of n, as the central limit theorem
says they should, and the estimates settle.

The dots on the left are every block of five queries. On WN18RR, a five-query
study of whether the top path beats chance could have reported anything from
minus 0.51 to 0.33. At full size the interval
is plus or minus 0.05. With five queries you would not just
be unsure, you could get the sign wrong.

## Demo recording (length of the real run)

For each query it prints the answer and NBFNet's own top paths. Every line
after that is a fresh forward pass on an edited graph.

First the top paths are deleted together, and the answer drops. Then the same
number of random edges, the control, and the answer stays where it was. Then
only the busiest edge, the one most of the paths share, with the share of the
effect it carries on its own. Last, the final hop is rerouted to another
entity, to see whether the probability moves with it.

It does this for five queries in a row, and every one finishes every
intervention. At the end it reads the full benchmark off disk, so these five
are visibly a slice of 800. Then a second run with a different seed
draws three new queries, and they complete too, so this is not one lucky draw.

## Slide 7, result 1 (45s)

The first result goes the method's way. Deleting the top five paths removes
86 percent of the answer's probability on WN18RR,
26 percent on FB15k-237, 43 percent on CoDEx-S and
37 percent on NELL23k. Deleting the same number of random edges
removes essentially nothing. So the gradient is pointing at part of the graph
the model really depends on.

The last row is a warning about a standard test. Keeping only the explanation
looks like a sufficiency check, but with so few edges left the rival answers
disappear too, and the answer's probability goes up on
36 percent of FB15k-237 queries. So I report it and do not lean
on it.

## Slide 8, result 2 (42s)

The second result: the order means very little. If the ranking were faithful,
Kendall's tau between the method's order and the real effect would be close to
one. It is minus 0.01 on WN18RR,
0.05 on FB15k-237, 0.08 on
CoDEx-S and 0.04 on NELL23k.

The path ranked first is the most damaging one 25 percent of the
time on WN18RR, where picking a path at random would manage
28 percent. This is the Hase et al. result from topic eight, one
domain over: where a method locates something does not predict what changing
it does.

## Slide 9, the bug (60s)

I tried to fix the ranking with integrated gradients, and the numbers did not
add up. Integrated gradients must sum to the total change in probability, and
they were far off. That led to a bug in the explanation code itself. The fast
kernel the model runs on sends each message one way along an edge. When a
gradient is needed, the code falls back to a generic layer that sends it the
other way. So the explanation differentiates a different model. On the left,
its scores are up to 10.50 logits away from the real model's. In
the middle, against a direct measurement, the released gradient is off by about
as much as the effect it is predicting, and it has the wrong sign
21 times out of 50. Running it on the reversed graph
fixes it: the error drops to 1 percent. The same code
is in NBFNet's own PyTorch Geometric release.

## Slide 10, the fixes (50s)

This figure changes one thing at a time. Blue is the explanation as released,
green is the corrected one, purple is the corrected one on the ULTRA paper's
own checkpoint, which reproduces that paper's accuracy, and orange is
integrated gradients re-ranking the same candidate paths. The fix leaves the
set-level result alone and raises Kendall's tau by about a tenth. Integrated
gradients raise it much more, to 0.49 on CoDEx-S and 0.45 on
NELL23k. That is the largest improvement in the study, and it is still well
short of one. So the bug explains part of the problem, not most of it.

## Slide 11, result 3 (48s)

The third result: is the list many explanations, or one? On WN18RR,
88 percent of the listed paths run through a single shared edge,
and only about 25 percent of the edges listed are distinct.
Deleting that one edge does 65 percent of what deleting all
five paths does.

Part of the reason is the last row. On WN18RR the reverse of the query fact is
often already in the graph, so one lookup answers the question, but it comes
back written out as several multi-hop paths. On the denser graphs the paths
really are different. The output looks the same in both cases, and nothing in
it tells you which case you are in.

## Slide 12, relation channels as neuromodulators (55s)

To push the study further I borrowed an idea from a NeurIPS 2025 paper by
Bull and colleagues on neuromodulation. In the brain, a few modulators are
broadcast widely and multiply the strength of many connections at once. That
gives a network a slow context that reshapes its fast content without
rewiring it.

ULTRA has exactly this structure. Its relation pass runs once per query and
gives one vector per relation type, and every message along an edge of that
type is multiplied by it. So each relation type is a channel that reaches all
of its edges at once. I give every channel a gain, turn it down from one to
zero like a dose, and compare that with the gradient at full gain, which is
NBFNet's own edge signal summed over the channel.

---

## Slide 13, result 4 (50s)

Here is the dose response. Silencing the strongest channel the explanation
uses removes 100 percent of the answer's probability on WN18RR and
90 percent on CoDEx-S, while a random channel removes almost nothing.

But look at the shape. At half gain only 19 percent of the full effect
is there on CoDEx-S. The channels behave like switches, not dials, and some
push the answer up before they bring it down, the inverted U that dopamine is
known for. The gradient is the slope at full gain, so it cannot see any of
this: even the corrected gradient gets the sign of the silencing effect
right only 59 percent of the time on WN18RR and
61 percent on CoDEx-S.

## Slide 14, what it adds up to (46s)

Put together: the method localises, and localising is not explaining. It finds
a region of the graph the model depends on, on all four graphs, against a
random control that never moves. As released it takes the gradient of the
wrong model. Fixed, it still does not rank inside that region well, it does
not split it into separate evidence, and it looks the same whether the model
reasoned over several hops or did one lookup.

The cheap fixes: reverse the graph before calling visualize, rank with
integrated gradients, report the busiest edge and confirm it with one
deletion, and print the distinct-edge count next to any list of paths.

## Slide 15, the control I found by reading an example (42s)

One more thing, found by reading a single example. On WN18RR the top path for
one query came back as a single hop. Asked what sociology is derivationally
related to, the model answers sociologist, because the graph already holds
that fact the other way round. That is true for 58 percent of WN18RR
queries. The test edge itself is never in the graph, so this is not leakage,
but it changes what there is to explain. Split on it, the redundancy and the
flat ranking hold on both halves. How much one edge carries does not.
