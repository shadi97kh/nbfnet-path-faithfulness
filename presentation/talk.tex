\begin{frame}{What this project does}
\centering

  \node[box, right=of m] (a) {answer\\\texttt{atheism}};
  \node[box, below=of m, fill=blue!6, text width=56mm] (e)
    {its own explanation: the top paths,\\read off \(\partial\,\text{score}/\partial\,\text{edge}\)};
  \draw[arr] (q) -- (m); \draw[arr] (m) -- (a); \draw[arr] (m) -- (e);
  \node[box, right=of e, fill=orange!10, text width=40mm] (i)
    {\textbf{this project:} change the graph and see if the answer moves};
  \draw[arr, dashed] (e) -- (i);
\end{tikzpicture}

\vspace{0.6em}
\begin{itemize}\small
  \item The paths are sold as the \textbf{provenance} of the answer. That is the
        whole case for paths over embeddings.
  \item A gradient says what happens if an edge changes \emph{a little}. Whether
        the model \emph{relied} on it is a question about removing it.
  \item So I audit the released explanation code by \textbf{intervening}, not
        inspecting: Topic~8's lesson, on a substrate where the edit is exact.
\end{itemize}
\end{frame}

% ------------------------------------------------------------------ method
\begin{frame}{Five interventions, on the graph itself}
\begin{center}\small
\begin{tabular}{lll}
\toprule
 & what changes in the graph & the question it answers \\
\midrule
A & nothing; call NBFNet's \texttt{visualize()} & what does the method claim? \\
B & delete each shortlisted path, one at a time & does its ranking match real effect? \\
C & delete the whole shortlist, or keep only it & necessary? sufficient? \\
D & point the last hop at a different entity & does the answer follow the edit? \\
E & turn one relation channel's gain from 1 to 0 & does the gradient predict the dose? \\
\bottomrule
\end{tabular}
\end{center}
\vspace{0.3em}
\begin{itemize}\small
  \item Every intervention removes or rewires real edges and reruns the model. No
        masks, no approximations, \textbf{no training}: the released checkpoint,
        every parameter frozen.
  \item Controls: the same number of \textbf{random} edges; the \textbf{bottom}
        of the method's own candidate list; the tail entity's \textbf{degree};
        whether the query's \textbf{reverse fact} is already in the graph.
\end{itemize}
\end{frame}

\(\bullet\) \allDeletions{} single-path deletions, plus joint deletions,

\(\bullet\) MRR on the \textbf{full} test set of each graph, with ULTRA's own

\end{column}
\begin{column}{0.43\textwidth}
\small
\textbf{Design choices that matter}
\begin{itemize}
  \item Queries drawn in a \textbf{fixed random order}, set before anything was
        measured. No picking.
  \item Only queries the model ranks in its top ten: explaining a mistake is
        a different question.
  \item Two graphs the model was trained on, two it never saw.
  \item Every interval is a 95\% bootstrap over queries. The model is
        deterministic, so queries are the only source of variance.
\end{itemize}
\end{column}
\end{columns}

% ------------------------------------------------------------------ the bug
\begin{frame}{Trying to fix the order, I found a bug in the explanation code}
\begin{center}
\includegraphics[width=0.97\textwidth]{../video/figs/direction_big.pdf}
\end{center}
\vspace{-0.6em}
{\small The fast kernel the model runs on sends messages one way along each
edge; the generic code \texttt{visualize()} falls back to, to get a gradient,
sends them the other way. So the explanation differentiates a
\textbf{different model}: scores up to \allDirGapMax{} logits off, gradient
off by as much as the effect (median error \allDirErrReleased\%), wrong sign on \allDirSignReleased{}
of \allDirN{} directions. Fix: run it on the reversed graph. Error then
\allDirErrCorrected\%. The same code is in NBFNet-PyG.}
\end{frame}

% ------------------------------------------------------------------ neuromodulation
\begin{frame}{Relation channels as neuromodulators}
\begin{columns}[T]
\begin{column}{0.48\textwidth}
\small
\textbf{Bull et al., NeurIPS 2025:} a few broadcast modulators multiply a
circuit's connections,
\[ W_{\mathrm{eff}} = W_0 + \textstyle\sum_k T_k\, n_k , \]
so a slow, low-dimensional \textbf{context} reshapes fast \textbf{content}
without rewiring it.

\vspace{0.6em}
\textbf{ULTRA already works this way.} Its relation pass runs once per query
and gives one vector \(q_c\) per relation type. Every message along an edge of
type \(c\) is \(h \odot q_c\): one channel reaching all of its edges at once.
\end{column}
\begin{column}{0.5\textwidth}
\small
\textbf{The pharmacology test}
\begin{itemize}
  \item Give each channel a gain \(g_c\); \(g = 1\) is the real model.
  \item Gradient \(\partial p / \partial g_c\) at \(g=1\): the slope. It is NBFNet's
        own edge gradient, summed over the channel.
  \item Dose response: turn \(g_c\) down to .75, .5, .25, 0.
  \item Channels the explanation uses, channels the gradient ranks first,
        random channels as control.
  \item Check: gain 0 on the explanation's edges reproduces the deletion
        result exactly.
\end{itemize}
\end{column}
\end{columns}
\end{frame}

% ------------------------------------------------------------------ takeaway
\begin{frame}{What it adds up to}
\begin{center}
\large The method \textbf{localises}. Localisation is not explanation.
\end{center}
\vspace{0.1em}
\begin{itemize}\footnotesize
  \item It finds a region of the graph the model depends on: true on all four
        graphs, against a random control that never moves.
  \item As released, it differentiates the wrong model. Fixed, it still does
        not rank within that region; integrated gradients rank better, still
        far from faithful.
  \item It does not decompose the region into separate evidence, and the list
        looks the same whether the model did multi-hop reasoning or one lookup.
  \item \textbf{Cheap fixes:} reverse the graph before \texttt{visualize()};
        rank with integrated gradients; report the busiest edge and confirm it
        with one deletion; print the distinct-edge count.
\end{itemize}
\vspace{0.1em}
{\footnotesize\textcolor{soft}{Limits: one model family; correct predictions only;
deleting a path disturbs paths that share its edges, which I measured and
report as a finding rather than argue away.}}
\end{frame}

% ------------------------------------------------------------------ backup
\begin{frame}{Backup: the control I found by reading an example}
\small
Building a worked example, the top ``path'' came back as one hop: the stored
reverse of a training fact. WN18RR keeps symmetric relations, so for
\wnRevPct\% of its queries one lookup answers the question. The test edge itself
is never present, so this is not leakage, but it changes what there is to explain.

\vspace{0.4em}
\begin{center}
\begin{tabular}{lcc}
\toprule
WN18RR & reverse present & reverse absent \\
\midrule
queries & \wnRevN & \wnNoRevN \\
paths sharing one edge & \wnRevBottleneckFrac & \wnNoRevBottleneckFrac \\
Kendall \(\tau\) & \wnRevKendallTauGradVsDrop & \wnNoRevKendallTauGradVsDrop \\
one edge recovers & \wnRevSingleEdgeRecoversFrac & \wnNoRevSingleEdgeRecoversFrac \\
\bottomrule
\end{tabular}
\end{center}
\vspace{0.3em}
Redundancy and the dead ranking hold on both halves. How much one edge carries
does not, which is why it is reported per graph and per half.
\end{frame}
